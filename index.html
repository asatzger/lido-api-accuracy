Lido Withdrawals API - Estimate Accuracy Analysis

About This Analysis

This analysis evaluates the accuracy of the Lido Withdrawals API's request-time endpoint, which estimates the time to withdrawal finalization for unfinalized stETH redemption requests within the Lido on Ethereum protocol.

Withdrawals API Overview

The Withdrawals API service provides utilities for estimating and tracking withdrawal waiting times in the Lido protocol. It serves two main use cases:

  • Pre-request estimation: Users can estimate waiting times before placing withdrawal requests
  • Request tracking: Users can monitor estimated waiting times for existing requests

Key Endpoints:

GET https://wq-api.lido.fi/v2/request-time?ids=1&ids=2

Calculate time to withdrawal for specific request IDs

GET https://wq-api.lido.fi/v2/request-time/calculate

Calculate time to withdrawal for current queue

GET https://wq-api.lido.fi/v2/request-time/calculate?amount=32

Calculate time to withdrawal for specific stETH amount

Testnet (Holesky):

GET https://wq-api-holesky.testnet.fi/v2/request-time?ids=1&ids=2

Notes

  • Analysis based on withdrawals that have both estimated finalization times and actual finalization times.
  • Positive errors mean that the actual finalization occurred later than estimated.
  • Negative errors mean that the actual finalization occurred earlier than estimated.
  • Data collected from DynamoDB table "lido_withdrawal_requests".
  • Withdrawals are processed in bulk once a day at roughly the same time.
  • Day-based accuracy metrics are more relevant than hour-based metrics due to the once-per-day processing pattern.
  • The processing patterns section focuses on unique withdrawals processed each day, not individual estimates.
  • For "Estimate Direction" statistics, estimates within ±1 hour of actual time are excluded (considered correct).
  • The "true lead time" reference line in the Error vs Leadtime chart shows the theoretical boundary with 24-hour steps.
